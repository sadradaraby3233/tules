What “VERIFIED” does and does not mean

VERIFIED = this device completed a WebSocket 101 handshake with the node's inbound at its exact path, with working TLS and SNI. That proves the port is open, the path matches, the certificate is trusted, and the node is reachable from your network right now — which is the failure mode that kills 90% of published free nodes.

It does not prove: the node forwards traffic to the open internet (browsers cannot use a node as a proxy), its bandwidth, its quota, or whether it logs you. A verified node can still be slow, capped, or snooping.

REACHABLE = TLS + HTTP answered, but the protocol (trojan / ss / reality-tcp) can't be dialled from a browser, so only reachability is proven.
NOT PROBEABLE = a browser cannot test this one (self-signed cert, or a browser-blocked port). It may still work in your VPN app, which is more permissive.
DEAD/BLOCKED = connect refused, timed out, or the path was wrong from here; another network may differ.

Free public nodes are shared. ~90% of the current US free pool has no transport encryption at all, and the "fast" ones are oversubscribed farms whose operators monetise your traffic (some even stuff Telegram ad text into the ALPN field). Fine for opening a blocked site; never for banking, logins, or anything you would not read aloud in a café. For a VPN you actually want to keep, run your own node — see the next section.
Want your own US node? Exact Railway steps (v2ray/Xray, no VPS bill)

Three facts that shape everything:

  1. Railway's Acceptable Use Policy prohibits "operating proxies or anonymization services" (railway.com/legal/acceptable-use). People do this anyway; it is also bannable. Do not put anything sensitive through it, and expect it to vanish someday.
  2. You don't get a dedicated IP. You get a hostname: xxx.up.railway.app (HTTPS/WebSocket, port 443) or name.proxy.rlwy.net:PORT (raw TCP). Outbound is a shared US IP — which is exactly what you want for unblocking, but it is not "one IP you own". Static outbound IPs exist as an add-on (railway outbound-network static-ip enable).
  3. Money: Trial = $5 one-time credit (~30 days, no card for the trial itself), then the Free plan gives $1 credit/month (1 vCPU, 0.5 GB RAM, 1 project, 0.5 GB volume). Egress is $0.05/GB, so $1 ≈ ~20 GB/month of traffic; Xray idling costs cents. Set a usage limit on day one.

Route A — RailPanel (the "rail panel on GitHub" you were told about):

  1. GitHub ▸ F0rc3Run/RailPanel ▸ Fork.
  2. railway.com ▸ sign in with GitHub ▸ New Project ▸ Deploy from GitHub repo ▸ install the Railway GitHub app if asked ▸ pick you/RailPanel. It auto-builds the Dockerfile (first build takes a few minutes: it downloads the pinned Xray core).
  3. Before anything else: service ▸ Settings ▸ Volumes ▸ Add Volume, mount path exactly /data. Without it every redeploy wipes your inbounds and clients — the container refuses to start without a writable /data.
  4. Settings ▸ Variables: set PANEL_PATH to something only you know (e.g. railpanel) and TZ to your zone. Do not set PORT — Railway injects it.
  5. Settings ▸ Networking ▸ Public Networking ▸ Generate Domain, target port 8080.
  6. Open https://<your-domain>/<PANEL_PATH>/ ▸ first sign-in is railpanel / railpanel plus a Railway API token (Account Settings ▸ Tokens) ▸ change that username/password immediately.
  7. Create your VLESS inbound, then Nodes ▸ Clients ▸ + and copy the subscription link from that client's row — one link that serves base64 to v2rayNG/v2rayN/Streisand/NekoBox/Karing, YAML to Clash Meta, JSON to sing-box/Hiddify, and shows a QR code in a browser. Set a traffic limit and an expiry on the client.
  8. Optional, for censorship-resistance: buy a ~$2/yr domain, put it on Cloudflare's free plan, then Railway ▸ Networking ▸ Custom Domain (target 8080) → add the CNAME in Cloudflare with grey cloud (DNS only) → wait for the certificate tick → switch to orange → Cloudflare SSL/TLS = Full (not Full Strict, not Flexible). Keep ALPN on http/1.1: if h2 negotiates, the WebSocket upgrade fails and every node dies. Then Nodes ▸ Generate turns one server into dozens of Cloudflare edge IPs.
  9. Region: service ▸ Settings ▸ Deploy region ▸ US West Metal (California, us-west2) or US East Metal (Virginia, us-east4-eqdc4a). Changing it redeploys and does not change your domain.

Route B — minimal DIY bundle (the files in railway-xray-bundle/: one Dockerfile + one start.sh, configs validated against Xray-core):

  1. bash <(curl -fsSL railway.com/install.sh) → railway login
  2. inside the bundle folder: railway init → railway up
  3. railway variable set UUID=<your-uuid> (else one is generated for you) → railway domain
  4. railway variable set MODE=ws DOMAIN=<the domain it printed> → railway up again → railway logs prints your ready-to-paste vless:// link. Paste it above in section 4 to verify it.
  5. Prefer raw TCP + Reality instead? Settings ▸ Networking ▸ TCP Proxy ▸ internal port 4433, then MODE=reality + TCP_PROXY_HOST/TCP_PROXY_PORT. Caveat Xray itself warns about: Reality on a non-443 port is more likely to be blocked by deep-packet filters — on hostile networks use the WebSocket-over-443 domain.

Other real options if Railway's rules or caps bother you: IRNova/Nova-Proxy (panel that lives on Cloudflare's free Workers plan), a $2–4/mo US VPS (Hetzner is EU; RackNerd/aeza/Cloudzy are US) with iPythoning/SUIWARP — read any install script before piping it to bash — or a paid VPN, which is the only choice with a support line.

Troubleshooting this page
  • Every fetch failed: your browser blocked the request. Open the file with Firefox on Android (Chrome sometimes restricts file:// network access), or paste the links themselves into the box in section 1 — parsing and probing still work.
  • No plain-ws:// probes: uncheck “hide nodes with no transport encryption” only if you accept the risk; browsers refuse insecure WebSockets from some origins. Those nodes are the unencrypted ones anyway.
  • “NOT PROBEABLE” everywhere: normal for trojan/ss/Reality — the browser can't speak those protocols. Test them in your VPN app's own latency check.
  • Slow/near-zero results: raise the timeout to 10000 ms and lower concurrency to 3 (mobile carriers throttle many parallel sockets).
  • Nothing is selected on export: tick rows manually; auto-select only picks verified/reachable ones.
